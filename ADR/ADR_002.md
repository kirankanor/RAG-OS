## ADR-002: One file per strategy

### Status
Accepted

### Context
Each stage (parsing, chunking, embedding, retrieval) has multiple strategies with
different, sometimes conflicting, optional dependencies (torch, faiss, openai, cohere).

### Decision
Each strategy gets its own file, registered via a decorator. Not grouped into one
file per stage.

### Reasons
- Avoids importing unused heavy dependencies
- Adding a strategy = one new file, nothing existing touched
- Easier to isolate and compare strategies individually

### Consequences
More files, slightly more boilerplate per strategy — acceptable trade-off.
